### 🟡 Importantes

#### R-01 — O ambiente de desenvolvimento não é reproduzível a partir do repositório

- **Eixo:** 1. Aderência ao plano
- **Referência cruzada:** T-02, primeiro critério de aceite; seção 7 do plano (README com instruções para rodar localmente)
- **Evidência:** `src/FloraBambini.Web/Program.cs:13-16`; busca por `user-secrets` e `localdb` em `README.md` e `CLAUDE.md` só encontra a menção genérica a LocalDB em `CLAUDE.md:18`
- **Descrição:** a aplicação lê `ConnectionStrings:Loja`, e o valor foi gravado no user secret da máquina onde a tarefa rodou. Nenhum arquivo versionado traz o comando ou o valor a usar. Quem clonar o repositório compila, roda os testes (que têm o servidor fixo no código) e recebe erro na primeira tela que tocar o banco. O critério "a aplicação abre conexão com o banco configurado em desenvolvimento" foi conferido uma vez, à mão, com `dotnet ef database update`; não há verificação que se repita.
- **Por quê é Importante:** o repositório é público e serve de exemplo para a turma da mentoria, e a arquitetura põe como meta que subir o projeto do zero exija apenas a connection string e as chaves do gateway (§3.1). Hoje nem a connection string está documentada.
- **Sugestão de correção:** acrescentar ao `README.md` uma seção curta de execução local com o comando `dotnet user-secrets set` e o valor para LocalDB, seguido de `dotnet ef database update`. O plano já prevê essa seção na checklist de prontidão (seção 7); a sugestão é antecipá-la, porque a T-03 em diante já depende do banco.

### 🟢 Sugestões

#### R-03 — Banco de teste fica órfão quando a execução é interrompida

- **Eixo:** 5. Qualidade do código
- **Evidência:** `tests/FloraBambini.Tests/Infra/BancoDeTeste.cs:41-45`
- **Descrição:** o banco só é apagado em `DisposeAsync`. Se o processo de teste for encerrado no meio (cancelamento, falha do host, depuração interrompida), o banco `FloraBambini_Testes_*` e seus arquivos ficam no LocalDB, e nada os remove depois. Com um banco por classe de teste e dezenas de classes previstas, o acúmulo é provável ao longo do plano.
- **Sugestão de correção:** como os nomes têm prefixo fixo, uma limpeza dos bancos com esse prefixo no início da execução resolve. Pode ficar para quando o incômodo aparecer.

#### R-04 — Connection string ausente só é percebida no primeiro uso do contexto

- **Eixo:** 5. Qualidade do código
- **Evidência:** `src/FloraBambini.Web/Program.cs:11-19`
- **Descrição:** a verificação está dentro da função de configuração do contexto, que só roda quando alguém pede o `LojaDbContext`. A aplicação sobe sem a connection string e falha na primeira requisição que usa banco. A escolha permite que os testes da T-01 subam a aplicação sem banco, mas em produção um erro de configuração apareceria para a cliente, não na publicação. Detalhe menor: a mensagem repete o literal `ConnectionStrings:Loja` em vez de usar `LojaDbContext.NomeDaConexao`.
- **Sugestão de correção:** quando a `AplicacaoDeTeste` passar a fornecer um banco, validar a connection string na inicialização.
